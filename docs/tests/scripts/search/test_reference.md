## Purpose

This test file checks the reference store: the small side collection where a person adds their own documents with tags, and the query script that finds passages in it. It covers adding with tags, matching by situation, the "no match" and "not set up" answers, replacing a document that is added twice, surviving an index rebuild, keeping one copy of a file that sits in the library folder when it is both rebuilt and added with tags, giving a path written with dots the same name the rebuild uses, picking up an edit when a file is added again, and making no network calls. Every document used is made up inside the test file.

## Behavior

One test class, `ReferenceStore`, is skipped as a whole when `chromadb` or `yaml` is missing {src:tests/scripts/search/test_reference.py:22-23}.

**Setup and teardown.** Each test makes a throwaway home, builds a child-process environment from it, and writes two Markdown files under `docs-to-add/`: a "design" note and a "security" note {src:tests/scripts/search/test_reference.py:24-30}. Teardown deletes the home {src:tests/scripts/search/test_reference.py:32-33}. The helper `query` runs `reference_query.py` {src:tests/scripts/search/test_reference.py:36}. The helper `add` passes each tag as a `--tag` flag {src:tests/scripts/search/test_reference.py:39-40}.

**Helpers for the library tests.**
- `library_chunks(name_part)` opens the references collection inside the throwaway environment and returns the metadata of every chunk whose `file` key contains `name_part` {src:tests/scripts/search/test_reference.py:117-120}. The `file` field is written at {src:scripts/search/build_index.py:410}.
- `make_library()` writes `design/seams.md` and `plain.md` under `vault/references` in the fake home and returns that folder {src:tests/scripts/search/test_reference.py:123-126}. That folder is where the code treats the references path as living by default {src:scripts/core/paths.py:50}, and the build lists it as a source root {src:scripts/search/build_index.py:277-282}.
- `_texts(name_part)` (a private helper placed after the last test) returns the stored passage text of every references chunk whose `file` key contains `name_part` {src:tests/scripts/search/test_reference.py:208-212}.

**Test cases, in file order (what each one proves).**

1. `test_not_set_up_without_a_store`: with nothing added, a query exits 2 and prints exactly `not set up` {src:tests/scripts/search/test_reference.py:42-45}. With no references folder the store opener returns nothing {src:scripts/search/refstore.py:76-78}, `search` returns `None` {src:scripts/search/reference_query.py:40-41}, and `main` turns that into exit 2 {src:scripts/search/reference_query.py:67-69}. A missing path setup raises `NotSetUp` and gives the same text and exit code {src:scripts/search/reference_query.py:61-63}, so the test cannot tell the two causes apart.
2. `test_add_then_match_prints_source_and_tag`: adding the `design` folder with tags `design` and `patterns` prints `tags: design,patterns`, and a query then prints `source: design/seams.md` and `tag: design,patterns` {src:tests/scripts/search/test_reference.py:47-54}. The docs sit outside the library folder, so the key lookup finds no references root that holds them {src:scripts/search/build_index.py:317} and returns `None` {src:scripts/search/build_index.py:326}, and the add falls back to a key that starts with the folder name {src:scripts/search/reference_add.py:47}. The tags are cleaned and sorted {src:scripts/search/refstore.py:64-66}, and the output line is built here {src:scripts/search/reference_query.py:75}.
3. `test_no_match_exits_zero`: a query of unrelated words prints `no match` and exits 0 {src:tests/scripts/search/test_reference.py:56-60}, matching the code path for an empty result {src:scripts/search/reference_query.py:70-72}. Whether the words fall under the score floor depends on the hash embedder, whose floor is 0.1 {src:scripts/search/embedder.py:45}.
4. `test_situation_maps_to_tags_from_references_yaml`: the test writes `references.yaml` next to the paths file, mapping `dev_implement` to `security` and `spec_define` to `design` {src:tests/scripts/search/test_reference.py:62-66}. A `dev_implement` query finds `secrets.md` and not `seams.md` {src:tests/scripts/search/test_reference.py:67-69}. A design-flavoured query under `dev_implement` finds nothing, and the same query under `spec_define` finds `seams.md` {src:tests/scripts/search/test_reference.py:70-73}. The map file sits next to the paths file {src:scripts/search/refstore.py:24-29}, the tags for the situation are read at {src:scripts/search/reference_query.py:44}, and the filter keeps only chunks that carry at least one wanted tag {src:scripts/search/router.py:242-245}.
5. `test_missing_map_searches_all_references`: with no map file and the situation `qa_review`, the security note is still found {src:tests/scripts/search/test_reference.py:75-79}. A missing situation gives no tags {src:scripts/search/reference_query.py:44}, and no tags means no filter {src:scripts/search/reference_query.py:47}.
6. `test_stakes_changes_the_floor`: runs a `low` and a `high` query and asserts only that both exit 0 {src:tests/scripts/search/test_reference.py:81-86}. The intended effect is a shift of +0.1 for low and -0.05 for high {src:scripts/search/config.py:130} added to the floor {src:scripts/search/reference_query.py:45}. See Notes: this test cannot detect a wrong shift.
7. `test_re_adding_replaces_instead_of_duplicating`: adding the same folder twice leaves one chunk in the collection {src:tests/scripts/search/test_reference.py:88-93}. The storing step deletes the earlier chunks of the same file and origin before inserting {src:scripts/search/build_index.py:404}.
8. `test_a_single_file_can_be_added`: adding one file with the tag `Security Basics` succeeds and the output contains `security-basics` {src:tests/scripts/search/test_reference.py:95-98}. 9. `test_bad_path_and_empty_folder`: a missing path and an empty folder both exit 1 {src:tests/scripts/search/test_reference.py:100-104}. 10. `test_rebuild_keeps_added_references`: after a full rebuild with the hash embedder the chunk count is unchanged {src:tests/scripts/search/test_reference.py:106-113}.
