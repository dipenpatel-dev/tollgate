## Purpose

This file tests that the Write and Bash guards stop the model from changing Tollgate's own files (settings, credentials, the `~/.tollgate` folder, the installer's `~/.claude/tollgate` folder and `~/.claude/tollgate-config` file, the files named by `TOLLGATE_CONNECTORS`, `TOLLGATE_PATHS` and `TOLLGATE_CONFIG`, the shell profiles and the repo `hooks` folder and `settings.json`), that the Bash guard checks a write placed after a newline, other separators or a substitution, and that the gate override Bash guard also catches file names built from pieces {src:tests/hooks/test_self_protection.py:5-6}. Each hook runs as its own process with a JSON payload on stdin, in a throwaway home folder. It has 16 tests in 6 classes. It was not run while this page was written, so each claim says what a test asserts.

## Notes

**Known limits of the code under test (not tested, and stated by the hooks or visible in them).**
- The file list is fixed: `~/.claude/commands` and `CLAUDE.md` are not on it, so the model can still write them {src:hooks/lib/protected_paths.py:28-32}. Gate approvals are plain `Status:` lines in ticket files; no ticket folder or state file is on the list either (searched `hooks/lib/protected_paths.py` for `ticket` and `state`, 2026-11-21: no hits). Only the `*-gate-override.md` name is guarded by the write guard {src:hooks/pre-tool-write-guard-path.sh:36-37}.
- The override guard reads only the command text. Its header lists a glob that hides the `gate-` part (`a-g*te-override.md`), a script that writes the file inside itself, encoded names and names built by code in a script file as not caught {src:hooks/pre-tool-bash-guard-gate-override.py:24-25}. A hard link made earlier under another name is also not seen, because the check works on the names typed in the command {src:hooks/pre-tool-bash-guard-gate-override.py:94-99}. No test covers any of these (searched the test file for `g*te`, `base64` and `os.link`, 2026-11-21: no hits).
- The Bash guard header says paths built from other variables expanded later and command substitution are not caught {src:hooks/pre-tool-bash-guard-code-dir.py:24-25}. The first still holds. The second no longer does: a write inside `$(...)` or backticks is split out and checked {src:hooks/pre-tool-bash-guard-code-dir.py:111-112}, and the tests above cover it. Only `$HOME`, `$TOLLGATE_HOME` and `$CLAUDE_DOTFILES` are expanded {src:hooks/lib/protected_paths.py:36} {src:hooks/lib/protected_paths.py:97-104}. No test tries another variable.
- The helper protects the repo folder found from its own file location, so the real Tollgate checkout is protected in these tests too, in addition to the fake repo set through `TOLLGATE_HOME` {src:hooks/lib/protected_paths.py:62-63}.

**Coverage gaps.** No test covers a bare subshell `(rm ...)`, which the guard does not catch because only `)` is split {src:hooks/pre-tool-bash-guard-code-dir.py:111}; text with a stray `)` or a heredoc body that looks like a write, which the guard denies by mistake; or a command with unbalanced quotes, where the guard falls back to a blank split {src:hooks/pre-tool-bash-guard-code-dir.py:122-125}. The Bash guard's fail-closed branch for a missing helper module is not tested; only the write guard's is {src:hooks/pre-tool-bash-guard-code-dir.py:44-49} {src:tests/hooks/test_self_protection.py:91-98}. No test uses `CLAUDE_DOTFILES`, `MultiEdit` or `Edit` payloads, or a protected path reached through a symlinked folder, only through a symlinked file {src:tests/hooks/test_self_protection.py:77}. The tests do not check the deny reason text.

**Description against code.** The Bash guard header still lists "interpreters writing through code (python -c, perl -e)" and command substitution as not caught {src:hooks/pre-tool-bash-guard-code-dir.py:24-26}; the code does check `python -c` and `node -e` bodies, and the test here relies on that {src:hooks/pre-tool-bash-guard-code-dir.py:231-232}. The protected-file test cases use only `python3` and `node`; `perl` is in the interpreter pattern but has no test there {src:hooks/pre-tool-bash-guard-code-dir.py:60}. The inline check needs a write word and a protected name in the same body, so code that builds the name from pieces passes {src:hooks/pre-tool-bash-guard-code-dir.py:203-207}.

**Machine dependence.** The tests use `os.symlink`, shell scripts and `python3` on the path, so they do not run on native Windows {src:tests/hooks/test_self_protection.py:77}. Hooks are started as executables and need their execute bit {src:tests/hooks/test_self_protection.py:32}. The Home classes keep the developer's other environment variables; a `CLAUDE_DOTFILES` value in the shell adds one more protected folder {src:hooks/lib/protected_paths.py:34} {src:hooks/lib/protected_paths.py:63}.

**Inputs without a check, and shared writes.** Every path and command in the tests is a constant or a temp path. In the code under test, the paths named in the command or the payload are resolved with `realpath` and compared; none is opened or run by the hook {src:hooks/lib/protected_paths.py:45-46} {src:hooks/lib/protected_paths.py:86-87}. The `TOLLGATE_HOME`, `CLAUDE_DOTFILES` and `HOME` values come from the environment with no check, and decide which folders are protected {src:hooks/lib/protected_paths.py:61-63}. Copying the write guard into a temp folder is the only file copy {src:tests/hooks/test_self_protection.py:94-95}; the temp home is removed after each test {src:tests/hooks/test_self_protection.py:48}. Nothing is written to a shared file.
