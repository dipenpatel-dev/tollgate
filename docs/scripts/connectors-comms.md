# Chat, tracker, notes, calendar and git connectors

Five connectors, all off until you use them. Setup is the same for each: `python3 scripts/connectors/connect.py on NAME` asks for the address and key and saves the key in your secret store (never a file) {src:scripts/connectors/connect.py:30} {src:scripts/connectors/connect.py:45}. With no setup, each prints `NAME: not set up` and how to set it up, exits non-zero and makes no network call {src:scripts/connectors/registry.py:325} {src:scripts/connectors/registry.py:326} {src:scripts/connectors/registry.py:435} {src:scripts/connectors/registry.py:436}. Framework rules are in `docs/scripts/connectors.md`.

Folder: `scripts/connectors/comms/`. It holds the five connector scripts and `comms_common.py`, the shared helper {src:scripts/connectors/comms/comms_common.py:2}. The helper also holds the secret redaction used by every connector here and by the Databricks schema export {src:scripts/connectors/comms/comms_common.py:64} {src:scripts/connectors/data/databricks.py:36}. Tests: `tests/scripts/connectors/comms/run.sh`.

## How they fit

1. The cache pullers (`jira`, `calendar`, `git-commits`) write `<name>.json` in the format `docs/scripts/cache.md` describes, so `daily_brief.py` reads them with no change {src:scripts/connectors/comms/comms_common.py:11} {src:scripts/connectors/comms/comms_common.py:12} {src:scripts/connectors/comms/comms_common.py:44} {src:scripts/connectors/comms/comms_common.py:51}. Records pass through the identifier filter first; a dropped record is counted, never logged {src:scripts/connectors/comms/jira_connector.py:122} {src:scripts/connectors/comms/calendar_connector.py:228} {src:scripts/connectors/comms/commits_connector.py:142}. Then every string in the kept records is redacted: a secret becomes `[REDACTED:LABEL]` in place and is counted by label {src:scripts/connectors/comms/jira_connector.py:149} {src:scripts/connectors/comms/calendar_connector.py:229} {src:scripts/connectors/comms/commits_connector.py:143}. `slack` and `notion` apply the same two steps to message text and note lines, in the same order, filter first and redaction second, before they write {src:scripts/connectors/comms/slack_connector.py:88} {src:scripts/connectors/comms/slack_connector.py:91} {src:scripts/connectors/comms/notion_connector.py:175} {src:scripts/connectors/comms/notion_connector.py:180}. Notion redacts the title too, before the file name is built {src:scripts/connectors/comms/notion_connector.py:179}.
2. Every run adds one line to the run log (fixed words only). A failed pull writes no cache file and still exits 0, so a scheduler does not loop {src:scripts/connectors/comms/comms_common.py:58} {src:scripts/connectors/comms/comms_common.py:59} {src:scripts/connectors/comms/comms_common.py:105} {src:scripts/connectors/comms/comms_common.py:110} {src:scripts/connectors/comms/comms_common.py:114}.
3. Nothing is hard coded. Workspace, channels, calendars, query, repo folders and time zone come from the connector entry or flags {src:scripts/connectors/comms/slack_connector.py:11} {src:scripts/connectors/comms/slack_connector.py:301} {src:scripts/connectors/comms/calendar_connector.py:198} {src:scripts/connectors/comms/calendar_connector.py:200} {src:scripts/connectors/comms/commits_connector.py:125}.
4. Privacy: message text, ticket titles, event titles and commit subjects are never printed or logged. Output is counts only, plus the number of secrets redacted by label: `0 secrets redacted`, or for example `2 secrets redacted (CREDENTIAL 1, SLACK_TOKEN 1)` {src:scripts/connectors/comms/comms_common.py:92} {src:scripts/connectors/comms/comms_common.py:111} {src:scripts/connectors/comms/comms_common.py:155} {src:scripts/connectors/comms/comms_common.py:156} {src:scripts/connectors/comms/slack_connector.py:24} {src:scripts/connectors/comms/slack_connector.py:25}. The note text, cache file and day copy do hold titles and text, but with secrets redacted. The run log keeps its fixed fields and holds no secret count; the count is on the printed line only {src:scripts/connectors/comms/comms_common.py:59} {src:scripts/connectors/comms/comms_common.py:113}. Slack and Notion also report their real count of dropped items now (`phi_dropped` for Slack, `phi dropped` for Notion) {src:scripts/connectors/comms/slack_connector.py:349} {src:scripts/connectors/comms/notion_connector.py:218}. The Databricks `schemas` export redacts secrets in table and column comments the same way {src:scripts/connectors/data/databricks.py:340}.
5. All HTTP goes through the `http` object the registry hands in {src:scripts/connectors/comms/comms_common.py:12} {src:scripts/connectors/comms/comms_common.py:13} {src:scripts/connectors/comms/comms_common.py:131}.

## Notes on each

- `jira` takes the search query with `--jql` and has `--dry-run`, which writes a fixture and makes no network call {src:scripts/connectors/comms/jira_connector.py:134} {src:scripts/connectors/comms/jira_connector.py:135} {src:scripts/connectors/comms/jira_connector.py:140} {src:scripts/connectors/comms/jira_connector.py:141}. It follows `nextPageToken` until the last page, with a page cap and a 500 ticket cap; hitting a cap gives a degraded result, not a failure {src:scripts/connectors/comms/jira_connector.py:35} {src:scripts/connectors/comms/jira_connector.py:36} {src:scripts/connectors/comms/jira_connector.py:37} {src:scripts/connectors/comms/jira_connector.py:96} {src:scripts/connectors/comms/jira_connector.py:108}.
- `git-commits` needs no key. It is a connector anyway so it stays off until asked. Turn it on with `printf local | python3 scripts/connectors/connect.py on git-commits --address FOLDER --key-stdin` {src:scripts/connectors/comms/commits_connector.py:13} {src:scripts/connectors/comms/commits_connector.py:14} {src:scripts/connectors/comms/commits_connector.py:17} {src:scripts/connectors/comms/commits_connector.py:18}. A folder that is a repo counts as one repo; otherwise each child that is a repo counts {src:scripts/connectors/comms/commits_connector.py:51} {src:scripts/connectors/comms/commits_connector.py:55} {src:scripts/connectors/comms/commits_connector.py:57}.
- `calendar` keeps a same-day copy in `state/calendar/` and reuses it on a repeat run; `--no-day-cache` forces a fresh read {src:scripts/connectors/comms/calendar_connector.py:176} {src:scripts/connectors/comms/calendar_connector.py:217} {src:scripts/connectors/comms/calendar_connector.py:203}. `--dry-run` writes a fixture and never feeds that copy {src:scripts/connectors/comms/calendar_connector.py:213} {src:scripts/connectors/comms/calendar_connector.py:236}. In `macos` mode it runs `osascript` and uses no network, but the connector must still be on {src:scripts/connectors/comms/calendar_connector.py:18} {src:scripts/connectors/comms/calendar_connector.py:19} {src:scripts/connectors/comms/calendar_connector.py:20} {src:scripts/connectors/comms/calendar_connector.py:161}.
- `slack` takes channels as `--channel ID=name` and direct messages as `--dm ID=name` {src:scripts/connectors/comms/slack_connector.py:301} {src:scripts/connectors/comms/slack_connector.py:302}. `--archive PATH` reads a local SQLite archive instead of the API and finds direct messages itself {src:scripts/connectors/comms/slack_connector.py:303} {src:scripts/connectors/comms/slack_connector.py:323} {src:scripts/connectors/comms/slack_connector.py:325}. The cursor (newest message time per channel) is `state/slack/cursor.json`; `--full` ignores it {src:scripts/connectors/comms/slack_connector.py:272} {src:scripts/connectors/comms/slack_connector.py:305} {src:scripts/connectors/comms/slack_connector.py:319} {src:scripts/connectors/comms/slack_connector.py:342}. Output goes to `<conversations>/slack/channels/<name>/` and `.../dms/<name>/`, one file per month {src:scripts/connectors/comms/slack_connector.py:21} {src:scripts/connectors/comms/slack_connector.py:22} {src:scripts/connectors/comms/slack_connector.py:126}.
- `notion` takes `page ID` or `database ID` {src:scripts/connectors/comms/notion_connector.py:12} {src:scripts/connectors/comms/notion_connector.py:13}. Pages include nested blocks to depth 3 {src:scripts/connectors/comms/notion_connector.py:36} {src:scripts/connectors/comms/notion_connector.py:121}. The note file is `<slug>-<id8>.md` and a rerun overwrites it {src:scripts/connectors/comms/notion_connector.py:181} {src:scripts/connectors/comms/notion_connector.py:184}.
